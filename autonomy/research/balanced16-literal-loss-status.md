# Balanced16 independent literal loss audit

`cohort/sustained_literal_loss.py` reconstructs single-frame focal, sine-difference smooth-L1 box and direction cross-entropy objectives with NumPy, independently of Torch and the producer equations. It supports the reference objective and the preregistered positive-only weighting N_positive/(4*N_class), with zero weight for absent classes and unchanged negative focal terms. Per-class positive/negative focal contributions and positive anchor counts are retained. Missing losses, mismatched arrays/labels, NaNs and wrong reported values are refused explicitly.

`cohort/audit_sustained_loss.py` externally binds the exact manifest/report/all16 heads and original native observations/targets/report hashes, verifies evaluation identity/order, and checks each literal objective against the producer's recorded scalar losses (relative/absolute tolerance2e-5). The pilot launcher now adds a read-only CPU audit after each0/19/35 GPU replay, using immutable per-stage inputs and the retained checkpoint report/heads. This launcher branch has not yet run as part of new native GPU admission.

`balanced16-literal-loss-red-verified.json` records the missing independent implementation. `balanced16-literal-loss-preparation-v2-verified.json` records37 live Insula CPU groups. Tests compare literal equations with actual Torch objectives for all-present, absent-class and no-positive frames, reject invalid input/report values, and preserve contribution accounting.

`balanced16-literal-native-fixture-verified.json` validates all16 historical baseline2000 native frame heads against their original training receipt/file hashes and recorded evaluation losses. The adapter preserves original ordered losses and pins the original report/manifest; this is an auditor validation, not a new sustained training execution. All heads are read through direct read-only mounts: no tensor copying, hard links, checkpoint deletion or GPU allocation. The first fixture failed because a nested mount point did not exist in a read-only source; its log remains in `insula/balanced16-literal-native-fixture-v1/output/live.log`. The admitted v3 fixture provisions an empty mount directory before binding and completes in6.304s, peak RSS430,976KiB.

Observed historical class totals are4,788 vehicle,524 pedestrian,258 sign and56 cyclist positive anchors. The mean normalized positive focal contributions are0.1758494,0.0329089,0.0275699 and0.0052974, respectively. Cyclists contribute about2.2% of the mean positive focal loss. This is evidence of unequal optimization contributions, not proof of a causal explanation or reweighting improvement. Decision: **needs more evidence**; compare the preregistered class-balanced treatment on the same ordered16 frames, sustained native gates and unchanged budgets.

Native new GPU/reference/head admission, pooled V3 scoring, bounded sustained controller, gradient/ranking diagnostics and verified HDFS checkpoint retention remain open. Historical metric curves used their original decoder and are not matched V3 scientific controls. No held-out claim follows from this audit.

`balanced16-literal-native-refusals-verified.json` records three actual worker probes on those historical native tensors. Freshly externally hashed reports with a NaN loss, incorrect finite classification loss, or wrong frame identity are all refused without an acceptance output. These probes pass file-hash admission and exercise numerical/identity validation rather than merely hash mismatches.
