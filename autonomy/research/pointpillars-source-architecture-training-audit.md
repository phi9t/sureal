# PointPillars architecture and training audit

Date: 2026-10-01. Scope: source reading and current code inspection; no implementation changes or new training. Source repository URLs use its mutable `master`; pin a commit before implementing parity tests. This is an architecture/training audit, not an independent validation of the latest scoring receipt.

## Architecture that we actually trained

The local `pipeline/pillar_encoder.py` decorates XYZ/intensity with XYZ cluster offsets and XY pillar-center offsets, then applies a bias-free 9→64 linear layer, padded-slot BatchNorm, ReLU and pointwise max. Scatter produces a 64×512×512 pseudo-image. `pillar_detector.py` runs 4/6/6 convolution stages with widths 64/128/256 and strides 2/4/8, upsamples each to stride two with 128 channels, and concatenates 384 channels. Three 1×1 heads produce four class logits, seven residuals and two direction logits for each of eight anchors per cell: 524,288 proposals per frame. Labels, lineage and annotation metadata are outside the model inputs.

The paper describes this PFN/backbone/head decomposition; car uses first-block stride two, while pedestrian/cyclist uses stride one. Its loss uses focal alpha .25/gamma 2, positive-anchor normalization, localization/classification/direction weights 2/1/.2, and a direction classifier to resolve the sine-angle ambiguity. It trains Adam at 2e-4, with .8 decay every 15 epochs over 160 epochs and batch 2 or 4. [PointPillars paper, sections 2–3](https://arxiv.org/html/1812.05784).

The local shared stride-two four-class head is therefore a Waymo adaptation, not a faithful reproduction of both original class-specific networks. Its 0.25 m cells yield 0.5 m head spacing; especially small or thin objects need measured anchor coverage before any capacity conclusion.

## Verified compatibility and differences

**PFN padding is compatible.** The author implementation masks decorated inputs before PFN, includes padded slots in BN, and does not remask ReLU outputs before max pooling. BN eps=1e-3 and momentum=.01 match locally. Changing to masked pooling or masked normalization would be a deliberate experiment, not correction of a proven mismatch. [Author PFN source](https://github.com/nutonomy/second.pytorch/blob/master/second/pytorch/models/pointpillars.py).

**No verified missing class-prior initialization.** The author RPN constructs ordinary Conv2d classification, regression and direction heads without a special foreground-prior bias assignment in this file. Local code does likewise. RPN stage layout, explicit zero padding before stride-two convolutions, upsampling and flattening family also agree. Source inference has selectable anchor masking, score thresholds, NMS and center limits. [Author RPN and inference source](https://github.com/nutonomy/second.pytorch/blob/master/second/pytorch/models/voxelnet.py). A low foreground prior could still improve early optimization, but must be labeled a hypothesis rather than original-code parity fix.

**The selected source config and local configuration differ materially.** The author car config uses 0.16 m cells, 100 points/pillar, 12,000 pillars, one class/two anchors, assignment .6/.45, anchor-area masking, 1,000 pre-NMS and 300 post-NMS proposals, and post-center limits. It uses nearest-IoU matching and class-agnostic nonrotated NMS at .5 with score floor .05, so those families are not inherently deviations. Its optimizer config includes weight decay .0001 and explicit decay. Training includes object perturbations, global rotation/scaling and database sampling. [Author car config](https://github.com/nutonomy/second.pytorch/blob/master/second/configs/pointpillars/car/xyres_16.proto).

Locally: 20,000 pillars×32 points, eight training-median class/yaw anchors, all-class .5/.35 assignment without pruning, class-agnostic enclosing-rectangle NMS pre4096/post500, no decoder center filter, Adam1e-4/zero weight decay/constant LR, batch one and gradient clip10. The actual `gpu/native-overfit.py` uses fixed cached observations/targets and no augmentation for 2,000 updates. These are declared adaptations; fixed no-augmentation input is appropriate for diagnosis, but does not establish an adequate main-study recipe.

## Why loss reduction is insufficient

The parent reports native APH≈.00569 despite 99.94% loss reduction. That juxtaposition makes detection behavior the next diagnostic, not an invitation to blindly increase network size. Initial classification near .5 across 2,097,152 sigmoid outputs per frame can dominate normalized focal loss; learning background suppression can dramatically lower total loss without learning reliable positive ranking or localization. The local default head initialization and positive-normalized loss make this plausible; attribution requires actual component curves, positive/negative logits and gradient measurements. A ratio against the huge initial total cannot independently prove object learning.

Other plausible mechanisms needing measurement: inadequate positive-anchor coverage, eligible objects losing physical support during pillar sampling, wrong-class competition, localization/heading error, train/eval BN behavior, and proposal suppression. Eight anchors compete across classes without class-specific assignment constraints. Thin sign anchors and stride-two layout deserve special inspection. None is established as the failure cause by source inspection alone.

## Ordered diagnostic and improvement program

1. **Frozen-checkpoint audit before retraining.** For every eligible GT, report maximum anchor overlap, assigned positives, retained point support, best same-class predicted IoU3D/BEV, center/dimension/yaw errors and positive scores. Report negative score quantiles and per-class AP versus APH. Verify exact-target synthetic heads recover eligible GT through full native export/scoring; this checks conventions without claiming trained quality.
2. **Separate ranking, regression and postprocessing.** Score current predicted boxes with oracle class/ranking only as an explicitly diagnostic counterfactual; decode trained positive anchors and inspect pre/post-NMS recall. Compare frozen predictions under class-wise versus class-agnostic suppression and proper rotated versus enclosing geometry. Do not retune on held-out data or replace preregistered primary scores.
3. **Inspect optimization.** Record classification/localization/direction curves, positive/negative focal contributions, unclipped gradient norms and clipping frequency, per-head gradients, and train-mode versus eval-mode losses/output errors. Diagnose using all16 fixed frames, not a cherry-picked example.
4. **One-factor retraining after diagnosis.** Candidate experiments: foreground bias prior; clipping policy; LR/schedule; class-specific thresholds/assignment or finer head spacing; point/pillar cap changes; normalization policy. Keep fixed16 inputs, seed, update budget and native scorer matched. Accept only independently live-verified native APH improvement plus target/support/resource reporting. Preserving failure results is required.
5. **Main-study recipe separately.** Develop geometry-consistent augmentation and a source-style optimizer/schedule candidate; audit transformed labels/heading/measurement lineage. Database sampling requires trustworthy point/box extraction, collision handling and train-only provenance. Re-register affected protocol before execution; tiny-overfit success does not establish generalization.

No architecture or optimizer change is recommended as an established remedy until frozen-checkpoint diagnostics identify the bottleneck. The overfit APH gate remains failed/open; the full held-out detection and encoder-comparison goal remains unchanged.
