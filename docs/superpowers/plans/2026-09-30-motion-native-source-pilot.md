# Native Motion source pilot

Goal: prove real v1.2.1 Scenario and corresponding historical sensor ingestion, causal projection, and native scoring in live TensorFlow-free Insula. This pilot cannot replace the later whole-scenario forecasting study.

Use `experiments/waymo-perception/research/motion-source-pilot.candidate.json` and its pinned authenticated inventory. Training and validation sources are separate. No Perception correspondence is inferred.

1. Wait for authoritative completion of the active Perception staging workflow before taking the shared raw lease. Rehash the inventory and candidate; match exact bucket/object/generation/size/MD5/CRC32C. Recompute retained raw bytes. Acquire one generation-pinned object at a time under the combined 2 GiB raw limit; the training pilot object is 448,622,357 bytes, validation is 273,686,917 bytes. A renamed source remains raw.
2. Preserve SHA256 and source generation in an immutable HDFS acquisition record. Verify HDFS readback before any raw eviction. The initial download, upload, and readback must not coexist as unaccounted raw copies. Use the authorized isolated GCS environment and sibling Waystone wrapper; credentials never enter artifacts or logs.
3. Run the existing bounded CRC32C TFRecord reader in locked CPU Insula over the complete acquired file. Pin a positive maximum record size and reject oversized records before allocation. Record every offset, index, length and payload hash. Clean terminal EOF and complete byte coverage are required; a later bad record prevents file admission. Independently check envelopes and native protobuf decoding with the pinned descriptor/runtime, including recursive unknown-field checks. Do not conclude compression from the directory name alone.
4. Inventory every native scenario_id, timeline/current index, track identity, target selection and extension fields. Reject duplicate scenario IDs and malformed identities. Before observing predictions, use a declared deterministic native-ID order to choose pilot scenarios within each official split. Retain the complete shard inventory and selected/excluded IDs; this is engineering selection, not the scientific cohort.
5. Resolve exact `uncompressed/lidar_and_camera/{split}/{scenario_id}.tfrecord` objects through authenticated metadata. Record missing extensions explicitly; no nearest-time or heuristic substitution. Acquire each extension under the same single-source ownership and verify native scenario_id matches the base. Reject duplicate augmentation and reconcile each historical/current timestamp and sensor count. Camera records are 256 codebook indices; pin the supplied codebook identity and verify index bounds. Raw RGB reconstruction is not claimed.
6. Feed acquired native truth to the current independently verified causal projection binary in its locked runtime, with separate immutable scoring truth and model-input outputs. Independently decode outputs, compare all permitted timestamps/states/signals and sensor indices, and prove no future or target-difficulty/interest metadata reaches observations. Inject future sensors, malformed timeline/IDs, and nested unknown fields into copies; all must fail without altering original truth. Strict sensor completeness must be tested against real source behavior; a mismatch requires an explicit contract correction and new live proof.
7. Score hand-checkable predictions on acquired target tracks through the native CLI with declared horizon, K, mode order, confidence and validity. Independently reconcile target IDs, track/time units, measurement counts and error calculations. Preserve missing-label counts rather than assigning perfect scores. Pooled multi-scenario and interaction/overlap parity remain separate mandatory gates before scientific forecasting comparison.

Acceptance: successful generation-pinned source/HDFS readback; complete live framing/protobuf inventory; exact supported scenario-extension correspondence or explicit missingness; causal projection and deliberate leakage rejection on native examples; native metric handoff with independent numerical/count agreement; current source/code/runtime/output hash receipts and measured storage, RSS and runtime. Failed or partial artifacts remain unpromoted. Recoverable raw cleanup must leave the bounded local slice and immutable recovery metadata intact.

Open scientific work: freeze whole-scenario train/development/held-out cohorts and extension coverage, train the tracks/maps baseline, compare LiDAR/camera-token/fused features under identical causal access and compute budgets, calculate scenario-level uncertainty, and publish adopt/reject/needs-more-evidence decisions.
