
For streaming evaluation, compute one scenario's `BucketedMetricsStats`, accumulate with `BucketedMetricsStats::Accumulate`, then finalize once. Preserve accumulators' `num_measurements` alongside reported means: empty accumulators produce zero, which is not evidence of perfect predictions. `Status` is Waymo's own `ok()/message()/status_code()` type, not `absl::Status`. [API](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/metrics/motion_metrics.h), [implementation](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/metrics/motion_metrics.cc), [status](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/common/status.h).

Input hierarchy is `ScenarioPredictions.scenario_id` → repeated `MultimodalPrediction` → repeated `JointTrajectories` modes with one `confidence` and repeated `SingleTrajectory{object_id, center_x[], center_y[]}`. All modes within one multimodal group must predict the same object-ID set. Scenario IDs must match; the complete predicted-ID set must equal IDs selected by `Scenario.tracks_to_predict[*].track_index`; track indices and IDs must resolve. Behavior prediction should use one object per multimodal group; joint prediction is evaluated as a group, with joint ADE/FDE averaging agents before minimizing modes. Output is `MotionMetrics.metrics_bundles`, keyed by object type and measurement step, containing minADE, minFDE, miss rate, overlap rate, mAP, soft mAP, and optional custom metrics. [Motion proto](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/protos/motion_metrics.proto), [validation and aggregation](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/metrics/motion_metrics.cc).

## Horizon, K, confidence, and validity

Default challenge configuration is 10 Hz tracks, 2 Hz predictions, 10 history samples, current sample at track index 10, and 80 future samples. Required target tracks have 91 states. Predictions have **16** x/y samples for 0.5 through 8 seconds. The implementation validates length as `future_samples * prediction_hz / track_hz`; the proto comment incorrectly includes history in its length formula. Source implementation controls. Prediction index `i` maps to track index `10 + (i+1)*5`, so indices 5, 9, 15 mean 3, 5, 8 seconds and ground truth indices 40, 60, 90. Never include time zero as a predicted sample. [Config/validation](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/metrics/motion_metrics.cc), [indexing helper](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/metrics/motion_metrics_utils.cc).

Default K is six. The evaluator takes the **first K serialized modes**, rather than globally selecting the K highest-confidence modes. ADE/FDE/miss rate ignore confidence; mAP sorts only that retained prefix by confidence. Overlap uses its highest-confidence mode. Confidence is an unnormalized score in the proto. For overlap, scores are normalized over all supplied modes first; a zero total becomes uniform. mAP uses raw scores across groups/scenarios, so per-object score normalization changes cross-object rankings. Recommended adapter preconditions are finite coordinates/scores, nonnegative scores, at least one mode, positive K, and K bounded by the supported model contract. These are adapter requirements, not claims that upstream validates them. Avoid interpreting logits as probabilities. The overlap implementation resizes confidence storage to K even when fewer modes exist; with nonnegative scores the real first mode wins zero ties, but negative scores can select nonexistent padded entries. [Mode truncation, overlap, AP](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/metrics/motion_metrics.cc), [normalization](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/metrics/motion_metrics_utils.cc).

ADE skips invalid sampled future ground truth states and divides by the number of valid samples. FDE/miss/mAP require a valid endpoint; a joint group is omitted if any member cannot be measured. An all-invalid ADE horizon has no measurement. Miss matching rotates error by the endpoint ground truth heading; lateral/longitudinal absolute errors must be within thresholds (equality passes). Thresholds at 3/5/8 seconds are respectively `(1,2)`, `(1.8,3.6)`, `(3,6)` meters, scaled from 0.5 to 1.0 according to current speed between 1.4 and 11 m/s. Overlap additionally needs all scene agents' ground truth boxes, current validity, future validity, and predicted-agent dimensions/orientation; checking positive intersection area excludes mere boundary contact. It compares against other valid agents present at current time, not just prediction targets. Current-validity and trajectory-shape validity affect AP classification separately. Standard mAP counts subsequent matches for a ground truth group as false positives; soft mAP ignores duplicate matches. mAP averages nonempty trajectory-shape buckets. [Metric implementation](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/metrics/motion_metrics.cc), [classification/geometry helpers](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/metrics/motion_metrics_utils.cc).

## Minimal ticket 19 verification fixtures

These are required proposed checks, not executed results:

1. A fully valid 91-state constant-velocity agent with unique ID, correct `tracks_to_predict`, and 16 exact future samples. Assert minADE/minFDE/miss/overlap zero and positive measurement counts for each horizon. Assert AP using a single populated trajectory bucket, without assuming all absent buckets contribute zeros.
2. Constant `(3,4)` meter offset: ADE/FDE equal five, then independently test heading rotation, threshold equality, below/above boundaries, and current-speed scaling. A deliberately shifted first prediction exposes accidental inclusion of current time.
3. Six bad modes followed by a perfect seventh; retained-prefix min metrics must still be bad. A perfect mode within the first six must rescue min metrics regardless of its confidence. Change confidence ranking to test overlap selection and AP ordering; cover all-zero confidence and reject malformed/negative/nonfinite adapter input.
4. One invalid interior future sample, invalid horizon endpoint, and all-invalid future samples. Assert denominators and omitted measurements, not only zero means. Add a two-agent joint case where one endpoint is invalid.
5. Two scene agents: disjoint boxes, positive-area collision, boundary-only contact, and an agent invalid at current time. Keep the second agent outside `tracks_to_predict` to prove full-scene overlap support.
6. Equal-confidence false/true positives, duplicated matching modes, and two populated trajectory buckets; validate PR tie ordering, standard versus soft AP, and dataset-level accumulation against independently calculated expected values.
7. Negative schema cases: scenario mismatch, missing/extra required IDs, inconsistent joint ID sets, wrong x/y length, wrong track length, invalid track index, and unsafe empty/K/horizon configuration rejected before native invocation. Upstream's measurement-step validation permits `step == prediction_steps` although indexing requires `< prediction_steps`; wrapper validation must enforce the stricter bound.

Run the pinned upstream `motion_metrics_test.cc` and `motion_metrics_utils_test.cc` unchanged in the TF-free build. The former embeds synthetic textprotos, so no external dataset download is needed for those regressions. Minimum recognizable evidence includes `ComputeMinADE` (expected ADE `5.97487`, FDE `8.53553`, tolerance `1e-4`), lateral/longitudinal miss and velocity-scaling tests, joint object/trajectory type tests, missing/invalid prediction tests, PR equal-confidence tests, and AP tests. Preserve upstream attribution and pin in evidence. [Upstream metrics tests](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/metrics/motion_metrics_test.cc), [upstream utils tests](https://github.com/waymo-research/waymo-open-dataset/blob/99a4cb3ff07e2fe06c2ce73da001f850f628e45a/src/waymo_open_dataset/metrics/motion_metrics_utils_test.cc).

## Unresolved constraints, kept separate

- **Source materialization:** Git objects are available at the pin; a populated checkout must be materialized and its identity recorded before the Docker COPY/build. This investigation used object reads and does not certify existing image contents.
- **Acquisition:** Native synthetic regressions need no downloaded Motion shards. A real validation result needs authorized Motion Scenario ground truth acquisition, exact release/shard identity, and parser/container framing provenance; those were not verified here.
- **Perception extension:** Existing perception observations do not automatically supply official Motion Scenario semantics. An extension must define world coordinates, stable IDs, full 91-state histories/futures, valid flags, dimensions/headings/velocities, target selection, and complete overlap scene context. A perception-derived extension score must be labeled as such unless equivalence to official Motion data is established.
- **Executable and protocol:** Upstream metrics tools at this pin provide no native `compute_motion_metrics_main.cc`; ticket 19 must implement and specify framing, streaming aggregation, failure behavior, prediction serialization, and machine-readable counts/provenance around the C++ API.
- **Build and runtime proof:** The existing CMake recipe excludes Motion. Compilation, linkage, upstream GTest pass counts, deterministic analytic outputs, and a real data smoke test remain implementation work. No training is required to establish the evaluator contract.
