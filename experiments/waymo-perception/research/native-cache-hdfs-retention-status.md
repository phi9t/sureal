# Native input cache retention

The balanced16 pilot requires a two-GiB reservation under the unchanged fifteen-GiB scientific payload limit. Releasing the eight expanded payloads after verified HDFS retention did not suffice. The older `overfit-native-cache-v1` is an input cache, separate from historical model-case payloads and the balanced16 inputs. Its 128 files are bound to 16 original independent native packing/target admissions.

`python cohort/publish_native_cache.py --release` uses bounded archive creation, authenticated HDFS upload and exact readback, live member verification and rehydration for every chunk, exact global manifest readback, and a separate independent live whole-cache admission. Only then can it release the original cache files. The global manifest preserves member names, byte counts, SHA256, archive recovery URIs and original receipt bindings. The host execution source closure is frozen and checked before all external/live operations and release. Failures preserve original cache bytes.

The initial attempt was stopped before release after review found missing host-source provenance bindings. Its partial HDFS chunks are not a whole-cache acceptance. All128 source files remained intact. Live CPU refusal tests now cover complete/changed/duplicate/unsafe cache admissions and missing/changed host source bindings (55 groups). The fresh real publication passed: 128 files / 1,040,757,892 bytes in 21 chunks, complete global manifest readback, and independent live whole-member recovery admission with five corrupt-copy refusals (1.208 seconds / 78,520 KiB RSS). All cache-local paths were then released; shared historical paths remain. Evidence: native-cache-hdfs-retention-verified.json, native-cache-hdfs-release-verified.json and native-cache-hdfs-inventory.json. Scientific unique-inode payload was 13,233,305,963 bytes afterward, leaving 2,872,821,397 bytes and satisfying the required two-GiB reservation.

After release, a historical replay that needs this input cache must rehydrate exactly the required members through the preserved manifests into a bounded scientific working set. The current balanced16 pilot reads its separate still-local native/physical/label inputs. This retention operation does not close fitting or held-out research gates.

Recovery: use the global publication_manifest_hdfs_uri in the retention receipt to locate each chunk. Download both archive_hdfs_uri and manifest_hdfs_uri into a bounded scientific staging directory, verify the pinned manifest SHA256, and invoke the frozen advanced/archive_worker.py in locked CPU Insula with mode rehydrate, the external manifest SHA256 and max_bytes=67108864. Every restored member must match the cache inventory SHA256. Select the required frame members from the restored chunk; retain all admission/receipt members when rebuilding the original cache tree. Reserve archive, download and uncompressed recovery sizes before writing. Never create an unbounded full-cache copy outside the scientific cap.
